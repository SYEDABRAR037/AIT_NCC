# BSR-05 Application Change Map

**Status:** File/function map for future implementation. This task changes documentation only. No code changes are authorized or made here.

## Guiding implementation order

Start with the disposable DB harness implementation and its tests. Do not begin schema/migration work until the harness cannot target an existing DB and has passed its negative-path unit/mock checks. Then implement migration-role SQL, run only on a new identity-verified disposable database, and build the PostgreSQL adapter behind a disabled route boundary. Manual attendance remains unchanged during the BSR-05 store step.

## Lock-order change inventory

Before challenge code is connected, inspect and update any operation that can overlap these rows:

| Operation | Current path | Required order and recheck |
|---|---|---|
| Login/session creation | Auth controller and session policy | Create durable AuthSession before returning token. |
| Logout/revoke presented | Session policy/logout handler | User row then AuthSession row; compare-and-set revokedAt. |
| Revoke all/password reset | Auth/recovery controllers | Lock affected User rows sorted, then AuthSession rows sorted; revoke atomically and audit if required. |
| Challenge issue | Existing controller + Map store | New routine locks User, AuthSession, TrainingSession, then GLOBAL/SUBJECT quota; inserts challenge and counts atomically. |
| Challenge consume | Existing controller + Map store | Same parents, then quota, then challenge; consume and decrement atomically. |
| User deletion/deactivation | Account administration utilities | User then AuthSessions; challenge children/quota cleanup before parent delete. No bare ORM cascade while challenge rows exist. |
| TrainingSession close | endAttendanceSession | Actor User/AuthSession then TrainingSession; status/eligibility recheck under lock. |
| TrainingSession deletion | Admin/session cleanup path if present | TrainingSession parent lock then quota/challenge cleanup; restricted challenge FK blocks uncontrolled delete. |
| Manual single mark/correction | markAttendance | Actor/target Users sorted, actor AuthSession, TrainingSession, attendance key; preserve current correction/leave rules. |
| Manual bulk import | bulkImportAttendance | Actor/session locks; sort all affected user/attendance keys; retain current per-record commit behavior unless separately approved. |
| Attendance audit | Existing manual/biometric transaction | Required audit in same transaction where critical; audit last; notifications only after commit. |
| Challenge cleanup | New cleanup worker | GLOBAL quota then sorted SUBJECT rows then bounded challenge rows; never lock parents afterward. |

This map does not assert all paths currently use the required order. Current design states they do not; a source-level audit and concurrency test are prerequisites.
